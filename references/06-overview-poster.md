# 06 · 行程地图总览海报（Overview Poster）

逐日小地图回答「这一天怎么走」，海报回答「整片区域玩什么、按什么顺序」。
当目的地天然分成相距很远的几块（如山地城市 + 千里外荒漠区），**一块区域一张海报**，不要硬塞一张。

## 1. 产物与位置

- 源文件：`posters/poster.html`（单文件，起步复制 `assets/poster-scaffold.html`），URL 参数 `?r=<region>` 切换多套数据。
- 渲染产物：`posters/<区域中文名>必游景点地图.png`（全尺寸 1500×1050 源图，本地存档、**不进 git**）。
- 发布产物：PIL 压缩后的 `assets/posters/<region>-map.jpg`（q82/progressive，目标 200-350KB），主攻略引用它。
- 嵌入位置：**简洁版**「逐日行程」上方，多张时上下堆叠（不要横排），每张配一行说明文字（地理分布 + 推荐走法）。

## 2. 版面契约（1500×1050 固定画布）

```
┌──────────────────────────────────────┬──────────┐
│ titleBox 标题+副题（左上 348px）       │          │
│ legend 图例（左上第二块）             │ 右侧卡片列 │
│                                  compass  │ 396px    │
│           Leaflet 底图（Esri Topo）  │ 编号+点位 │
│                                      │ 卡片 6-8  │
│ route 推荐路线 seq（左下 380px）      │ 张为上限  │
└──────────────────────────────────────┴──────────┘
```

- 右侧列预留：`fitBounds` 的 `paddingBottomRight:[420,118]`、左上 `paddingTopLeft:[78,24]`，保证点位不被卡片和标题压住。
- 底图固定 `leaflet@1.9.4` + Esri World_Topo_Map，禁其他瓦片源；比例尺 `L.control.scale` 放右下。
- 配色语义固定：base 红星=大本营（住多晚的城市）、其余颜色按「线路/主题」分（如跟团主线、半日往返、市区慢逛、备选），**灰色专留给备选点**，主线改了备选要一起降级为灰。

### DATA 字段
- `points[]{id,lat,lng,name(英文优先，别中英混排),c,base?,mk:[dlat,dlng] 视觉错位,la:lab 偏移}`；
- `routes[]{pts:id 数组,c,dash}`：实线去程/主线，虚线返程或半日往返，备选用灰虚线；
- `cards[]{id,c,nm,en,tag,imgs(th 缩略图路径),tips(2-3 条短句)}`：一个 id 可合并两个相邻小点位（id 写 `"7·8"`），避免卡片超 8 张溢出画布；卡片缩略图取图库 `*.th.webp`，缺图 `onerror` 隐藏；
- `seq[]{t,pts,c}`：左下角编号路线，顺序必须与最终行程一致（如 `D2/D3` 分两行）；
- `meta[]`：车程/团费等一行结论，数字来自可复现计算或已查证来源。

## 3. 防重叠铁律（每张海报必须截图调到位）

1. **密集近邻点用 `mk` 人为错位**（度→像素按当前尺度换算，横向 1°≈30px 时错位 0.05-0.25），label 再用 `LABELPOS` 指定 top/bottom/left/right 四个方向散开；改完必须看渲染图，不允许标签互相压字。
2. 最东侧/最北侧的点别让 label 超出画布或钻到右卡列底下；必要时收紧/外扩 `bounds`（如东侧留 0.15-0.2° 余量）。
3. 大本营星标与市区步行点必然重叠，市区点一律 mk 错位到星标四周，并让步行路线形成可见小环。
4. 标签只放英文/缩写（CAN/ALA 这类），中文标签只出现在右侧卡片里。
5. 点位坐标为近似值时，落图后核对是否在已知公路/城镇连线上，不合理就微调。

## 4. 渲染流水线（browser-use，必须定视口截全幅）

1. `bu.cdp("Emulation.setDeviceMetricsOverride",width=1500,height=1050,deviceScaleFactor=1,mobile=False)`；
2. `bu.navigate(file://.../poster.html?r=xxx)` → `wait_for_load` → 再 sleep 4-5s 等瓦片；
3. 校验 `window.__ready===true`，截视口图即全幅海报（普通视口截图会被滚动条裁切，必须先定视口）；
4. 复制为中文 PNG 存档 → PIL 转 JPG q82 progressive 覆盖 `assets/posters/`；
5. 一套数据改完两个区域都要重渲染；行程一变，海报 routes/seq/cards/legend 必须同步，不允许海报停留在旧行程。

## 5. 与主攻略的一致性检查

- 海报编号点必须能在逐日时间轴找到对应天；被移出主线的点（如拼团升级才去）只能以灰色「备选」出现，卡片 tips 写明「哪种团型才经过」。
- 海报文案口径与时间轴一致（例：新版徒步起点/方式变了，就删掉旧版「必须越野车/搓板路」这类过时描述）。
- 验证时除桌面外，简洁版手机端海报要 `width:100%` 自适应上下堆叠，不横滑不裁切。
