## 1. 内网红黑经验采集（红黑经验的主来源）

> **环境门禁（先判断再执行）**：内网采集（enterprise_agentic_search、飞书 IM、lark-doc/lark-wiki 等）
> **仅对 ByteDance 内网用户启用**。判断为非 ByteDance 内网环境（无企业身份/内网工具不可用/未登录企业账号，
> 或用户明确不是字节员工）时，**整段跳过**：不调用任何企业内部工具、不等待内网权限、不把缺内网数据当成阻塞；
> 直接以公开渠道（公开搜索 + 小红书模拟人工 + 官方源）作为唯一情报源，红黑经验改从公开游记/评论提炼，
> 并在需求文件与成稿里注明「无内网来源，红黑均来自公开样本」。判断不确定时先问一句用户是否在字节内网，再决定走哪条路。

1. 先读 `doubao-enterprise-search` skill 再用 `enterprise_agentic_search`；用**完整自然语言整问**，一次合并子问题，
   例：「同事们关于 X 目的地的行程安排、必去景点、美食住宿、交通方式、踩坑经历和分享过的攻略文档有哪些？」
2. 需要精确到群消息时走飞书 IM skill：`chat-search` 定位旅游群 → `chat-messages-list` 拉时间线 →
   `messages-search` 按「避坑/门票/堵车/酒店/排队/宰客」等关键词补漏；分享的文档链接登记到 sources.md。
3. 攻略文档本体用 lark-doc/lark-wiki 读全文，快照存 `raw/`，记录「文档名+链接+时间」。
4. 每条经验落 notes 时保留**说话人**（红黑榜可署名「张三 25 国庆实测」这类可信锚点）。

## 2. 公开事实核验

- 签证/入境/时区/节假日政策：使馆、外交部领事服务网、目的地官方门户优先；**专门查近年政策变更**
  （例：哈萨克斯坦 2024 年才全境统一 UTC+5，旧攻略时区是错的）。
- 航班/火车班期：查「星期几有哪班」的完整班期表（Yandex 时刻、携程国际、FlightRadar24、航司官网交叉），
  不能因为「航线存在」就假设当天有班；记录航司、航班号、班期规律，行程中标「出票复核」。
- 营业时间/门票/预约：官方页 + 最近 3 个月游记交叉；注意周闭馆（如博物馆周一/周二闭馆）、
  集市仅周末开、礼拜场所周五不开放等「星期约束」，直接影响排程。
- 距离/里程：坐标用 haversine 工具现算（航空大圆距离），公路里程查地图路线，区分「航空约值/公路约值」。

## 3. 小红书模拟人工采集 SOP

**默认且唯一路径：browser-use 系 skill（mac_computer_use_tool + seed_browser_use），像人一样点页面。**
禁止写 HTTP 爬虫直拉搜索接口/笔记接口/CDN 列表——会触发风控甚至封号。

### 3.1 流程
1. 登录态：未登录/验证码/扫码一律 `interaction.request_action(type=browserControl)` 交用户扫码，不猜密码不绕验证。
2. 关键词矩阵：为**每个点位/店名单独组关键词**（「地名」「地名+攻略」「店名+城市」「地名+月份」），
   不要用泛词大搜后凭标题猜内容——泛搜正是图文不符的根源。
3. 逐帖操作（observe-act-observe）：搜索 → 点进笔记 → 等加载 → 慢速滚动 →
   读正文 → **展开并读全部评论**（有效信息大量在评论：真实耗时、避坑、闭店、价格、定位纠错）→ 记录。
4. 节奏拟人：每帖停留数秒、帖间停顿、分批进行；不要连续高频翻页；**后台运行**（不 switch 到前台抢用户窗口），
   用户操作其他窗口时流程不应依赖页面在前台。
5. 防漂移：每处理几帖就校验当前 URL 仍在「该关键词的搜索结果/对应笔记」；一旦被推荐流带到 explore 首页，
   立即回到搜索结果页重来（推荐流内容与关键词无关，是串图重灾区）。
6. 时间窗：优先目标出行月份（如 9-10 月）样本；季节无关项（博物馆/餐厅/地标）补充其他月份样本，报告中分层标注。

### 3.2 落盘结构（raw/xhs/，不发布）
- `scan/`：每关键词的扫描清单（笔记 id/标题/赞藏/初步判定）。
- `imgs2/<点位key>/<笔记id>/`：该帖候选图（**按关键词分目录**，新一轮采集换新根目录，避免与历史废图串用）。
- `sheets2/`：逐帖工作表（正文摘录、评论要点、Gate 判定、图片逐张判定）。
- `notes_read.jsonl`：深读记录。样本口径：扫描 ≥ 数百篇、深读数十篇、评论上千条量级；样本太少要明说，不硬下结论。
- **每一轮新关键词批次换新根目录**（imgs1/imgs2/imgs3…），物理隔离历史废图，避免构建时与旧图串用。

### 3.3 浏览器实操防风控与高效采图范式（实战踩坑验证，mac_computer_use_tool + bu）

以下每条都来自真实触发风控后的复盘，默认照做：

1. **笔记 URL 必须带搜索卡片 href 里的 `xsec_token`**：从搜索结果卡片取完整 `explore/<id>?xsec_token=...&xsec_source=pc_search` 链接点入；手敲裸 `explore/<id>` 会跳「你访问的页面不见了」。
2. **一个 cell 内禁止快速连续直跳多帖**，会触发 **300017 安全限制**。恢复手法：回搜索结果页 → `bu.find`+`bu.click` 真人点卡片 → 每帖间隔 2-4 秒、慢速滚动 → `Esc` 关帖回搜索页再点下一帖；不要硬刷连点。
3. **防漂移**：每处理几帖校验当前 URL；一旦被推荐流带到 `explore` 首页（无关键词），立即回搜索页重来——推荐流帖子正是串图重灾区。
4. **后台运行**：只通过 bu 操作已附着的 tab，不 switch 到前台抢用户窗口；用户操作其他窗口时流程不应依赖页面在前台。
5. **取图高效范式（别和灯箱较劲）**：真人点进帖子 → JS 取 `.swiper-slide img` 的全部图 URL（过滤 avatar、xhscdn 头像、去重），含 `<video>` 的视频帖直接跳过；灯箱左右箭头坐标不稳定、swiper 实例常取不到，不要依赖翻灯箱。
6. **下载走浏览器本身**：用 `bu.download(url)` 经 Chrome 下载到 ~/Downloads（符合「浏览器人工下载」约束），**每帖下完立即 mv 到该帖专属目录再开下一帖**——否则同名文件产生 `(1)/(2)` 后缀，批量 mv 会把不同帖子的图串在一起。
7. **签名 URL 当天过期**：xhscdn 链接带日期签名，隔日重开帖子重新取 URL，不缓存跨天用。
8. **Gate-2 用联系表目视**：一帖几十张逐张打开太慢；用 PIL 拼 4-6 列联系表（contact sheet），`Read` 联系表一次性逐格判定，再按编号回选原图，判定口径写进工作表，可复查。

## 4. 双 AI Gate 实拍管线（质量核心）

### Gate-1 · 审帖（帖子与点位强相关才放行）
逐帖判定：主题是否就是该点位/该店？排除「只提一嘴」「同名异地」「纯广告拼贴」「视频笔记（只取视频封面=视频内容，跳过）」。
餐厅必须满足：本店门脸/招牌/菜单/小票出镜，或正文+定位明确指名本店；泛菜品图不算本店实拍。

### Gate-2 · 逐张审图（图与点位强关联才入库）
对 Gate-1 通过帖子的每一张图单独判定：
- 通过：画面主体能确认是该点位（地貌形态/招牌/菜单/标志性结构可辨识）。
- 淘汰：大头人像/自拍合影、视频截图、转场文字图、泛天空马路、别家店、同帖但与点位无关的生活图、重复近 duplicates。
- 每点位目标 10 张有效图；不足就如实标注「N 张」，**绝不跨点位借图、不用泛类型图凑数**。
- 逐张判定用 3.3 的 PIL 联系表一次性目视：地貌类先写「该点位长什么样」的识别判据（颜色/层理/结构/标志性物体），
  再按判据逐格过；拿不准的一律淘汰，宁可少不可错。同一点位相邻事件在同一地点时，只给「目的地」那条配实拍。

### 入库与构建
1. Gate-2 选择结果写 `tools/gate2_select_<行程>.json`（点位 key → 选中的图路径列表）。
2. 运行 `scripts/build_gallery.py`（参数化行程目录），它会：
   - 把选中图**压缩**为 `assets/<gallery>/<key>/<key>_NN.webp`（主图长边 1280/q70，单张 ≤400KB）并同步生成 480px/q62 缩略图 `.th.webp`（缩略图默认产出，无需开关）；
   - 生成 `provenance.json`（每张图 ← 原笔记 id/链接/赞藏，保证可溯源）；
   - 生成 `gallery-data.js`，挂 `window.GALLERY = { key: {title, items:[{src,cap,url,like}]} }`，
     支持「聚合键」（如 citywalk_cathedral → cathedral）映射到实体目录。
   - **增量迭代用 `--merge`**：只重建 select 里出现的 key，其余旧 key 与索引原样保留，自动合并进现有 gallery-data.js/provenance.json，避免一次补点就全量重跑。
3. HTML 事件五元组第 5 位填 key，渲染时 `window.GALLERY[key]` 存在才出「实拍 N」按钮，缺键自动不渲染（不会出空按钮）。
4. 迭代时新增点位：新关键词新目录采集 → 双 Gate → 增量改 select → 重跑构建；旧图被否就从 select 删除并重建，物理废图留在 raw 不进 assets。

## 5. 口碑调研报告口径（小红书口碑调研报告.md）

固定写清：采集日期与方式（声明「登录态下模拟人工浏览、未用接口抓取」）、关键词清单、
扫描篇数/深读篇数/评论条数；每个点位给「N 篇提及」频次、共识结论、争议点、评论原话摘录、价格锚点、避雷对象；
季节样本与季节无关样本分开统计；末尾列来源说明与「出行前以官方页为准」。
